# 03_link_lost_failsafe: Сценарій два в одному:
# Перший варіант - HEARTBEAT оператора пропадає на 17.5 секунді, актуальні координати по цілям перестають надходити, але
# дрон вже в польоті до останньої розрахованої точки скиду, і якщо він досягає цієї точки скиду менше ніж за 
# --drop-refusal-timeout секунд (дефолт 5 сек), то ця розрахована точка скиду все ще може вважатись актуальною - є шанс влучити у ціль,
# допоки дані "свіжі", тому дрон долітає до точки та робить скид - звичайний Failsafe сценарій, дрон завершив місію атакою навіть при втраті зв'язку.

# Другий варіант - подібний до першого, але тут дрон не встиг досягти розрахованої точки скиду, похипка влучання кожен тік стає більшою,
# оскільки цілі рухомі, шанс влучити - щокроку менше, можна втратити снаряд даремно. Тому в цьому випадку дрон зупиняється та чекає на відновлення
# зв'язку з оператором (10 сек) та отримання даних по цілі. Підхід щось типу "best effort" за поточних (уявних) характеристик дрона,
# та способу (єдиного) отримання даних про цілі.

# Очікується: Armed -> Engaged -> Failsafe -> Engaged -> Complete;
# у simulation.json -- видимий перехід ... -> Decelerating -> WaitingForConnection ->  Stopped -> ... з замороженими
# dropPoint/predictedTarget на час очікування.

0.2 designate_targets
0.5 enable
17.5 heartbeat_drop 10
